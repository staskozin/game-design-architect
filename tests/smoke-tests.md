# Тестовые запросы для v0.1

Проверь Skill в новом чате с установленным плагином. Оценивай не слова «Input» в тексте, а полезность результата и отсутствие выдумок.

## Тест 1 — проектирование

**Запрос:** «Придумай два разных варианта престижа для небольшой инкрементальной игры, где игрок вручную обслуживает клиентов, а затем нанимает сотрудников. Выбери лучший и разложи на пять блоков».

**Ожидаем:** включён `mechanic-designer`; есть функция механики, выбор игрока, trade-offs, варианты, модель, feedback; числа баланса помечены как предварительные.

## Тест 2 — анализ

**Запрос:** «Я играл в Hexa Sort Puzzle: там перекладывают гексы в стопки и покупают удаление стопки, перестановку и обновление пула. Разбери механику, но не выдумывай скрытые правила».

**Ожидаем:** включён `mechanic-analyzer`; факты из запроса не смешаны с гипотезами; выделен core loop; нет выдуманного кода, аналитики и рейтинга.

## Тест 3 — короткое ТЗ

**Запрос:** «Напиши короткое ТЗ: под карточкой работника показывать, работает он, свободен или не нашёл подходящих котов. Существующие правила найма и расчёта награды не менять».

**Ожидаем:** включён `mechanic-specification`; коротко и проверяемо; есть источники состояний, обновление UI, сценарий отсутствия целей; не затронут баланс.

## Тест 4 — пограничные случаи

**Запрос:** «ТЗ: два свободных работника могут одновременно забрать одного кота, этого быть не должно. Доступ к коду пока не даю».

**Ожидаем:** предложено атомарное назначение/резервирование на уровне логики без навязывания конкретной технологии; нет вымышленных названий файлов; есть критерий однократного назначения.

## Тест 5 — отсутствие блоков

**Запрос:** «Проанализируй автоматически движущуюся платформу без управления игрока. Какие из пяти блоков здесь не обязательны?»

**Ожидаем:** Input может отсутствовать (платформа автономна); Communication может быть минимальной или отсутствовать; модель не притянута насильно к шаблону.

## Тест 6 — проверка обратной связи

**Запрос:** «Работник не берёт кота, хотя галочка разрешённой редкости включена. Предложи понятный игроку интерфейс без нового модального окна».

**Ожидаем:** отделён фактический статус от гипотез о причинах; inline-состояние и объяснение блокировки; нет предположения, что причина уже известна без данных.

## Регрессионный чеклист

- [ ] Каждый Skill правильно выбирается по цели.
- [ ] Все используют одинаковое толкование пяти блоков.
- [ ] Нет обязательных пустых секций и формальной многословности.
- [ ] ТЗ не меняет согласованный дизайн без разрешения.
- [ ] Анализ не выдаёт гипотезы за факты.
- [ ] Плагин работает без MCP.
